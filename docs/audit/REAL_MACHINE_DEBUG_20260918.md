# 真机联调记录 2026-09-18：5 个"整场白跑"级 bug

这一天从"车倒车进场后一动不动"一路查到"夹爪下压了却被自己否掉"。
下面每条都是**现场日志实证**，不是推测；每条都补了会在旧代码上失败的护栏。

---

## 1. 主循环第一帧就死：`UnboundLocalError: local variable 'now'`

**现象**：4 号区启动 → 自检全绿 → 倒车 1.5m 进场（正常）→ **进场地后车一动不动**，
只剩 `无动作 15s` 异常在刷保命绕圈。

**日志**：
```
autonomous_state: 📊 ...  （主循环第一帧）
autonomous_state: ⚠️ 主循环异常（累计 1 次，最近一次:
    UnboundLocalError: local variable 'now' referenced before assignment）
```

**根因**：`_run_once` 里 `now` 只在「策略状态 == DONE」分支中被赋值，
却在函数末尾的 2Hz 诊断日志里**无条件使用**。那次赋值让 `now` 成为局部变量，
于是只要策略状态不是 DONE（比赛绝大多数时间都不是），第一帧就抛异常。

**为什么整套验证没拦住**（这才是更该修的）：
- `hw_selftest/m_decision.py` 确实调了 `_run_once`，但它先把决策状态造成"时间到"，
  函数在终场收口分支就 `return` 了 —— **正文一行没执行**；
- 仿真走 `simulation/integrated_sim.py`，那里把控制循环**另写了一遍**，
  根本不 import `AutonomousState`；
- `pyflakes` / `compileall` 对"条件赋值 + 无条件使用"都不做数据流分析。

**佐证**：把坏版本塞回护栏，`DONE确认窗口` 与 `时间到终场` 两个场景**照样 PASS** ——
证明"只覆盖终场分支"的测法必然漏掉它。

**修复**：`now = time.time()` 提到函数开头无条件取一次。
**护栏**：`tools/fix_verifiers/verify_run_once_loop.py`（8 个场景，事故工况排第一）。
**顺带**：`_main_loop` 吞异常时**只打印第 1 次与每 250 次**，所以现场那句"累计 1 次"
实际是 222 帧全在崩。

## 2. 串口"劈行"：`_read_line` 双路径读同一字节流

**现象**：PING→PONG 握手 7% 要重发；ODOM 20Hz→13.9Hz、TEL 8.5Hz→1.1Hz。

**证据**（25 秒实测）：
```
_read_line 返回 1979 行，其中非合法前缀的碎片 482 行 = 24.4%
rx_buf 残留: b'ODOM,0.139961,-0TEL,666965,0,0.0IMU,666982,...'   ← 三行粘连
裸 pyserial 单路径读：PING→PONG 40/40 成功、p50 时延 10.6ms、0 个 ERR 行
```

**根因**：`_read_line()` 先非阻塞地把内核缓冲搬进 `_rx_buf` 找整行，找不到就退回
`self._ser.readline()` —— 两条路径读的是**同一个流**。`_pump_rx()` 恰好抓到半行时
（`PONG\r\n` 只到 `PO`），剩下的 `NG\r\n` 被 `readline()` 单独取走 → 该行被劈开，
`wait_for("PONG")` 永远匹配不上；残留半行还会和下一行粘成垃圾行。

**修复**：`_read_line` 只走共享缓冲一条路径，缓冲里没有整行就**继续往同一个缓冲追加**。
**效果**：碎片率 24.4% → **0.0%**；IMU 49.5Hz / ODOM 19.7Hz / TEL 9.9Hz（首次跑满协议标称）；
PING 92.9% → **100%**。

## 3. 视觉把"同学的腿"识别成"黑色正三棱锥"

**现象**：`BLACK → 核心物资` 每秒几十条刷屏，世界地图里冒出十几个幻影目标，
车跑去扑空。

**现场抓到的真实检测**（`/status` 原样）：
```
BLACK TRIANGULAR_PYRAMID 0.75  bbox=[0,   0, 100, 378]   ← 同学的腿
BLACK UNKNOWN            0.34  bbox=[407,289,  77, 191]
BLACK CUBOID             0.75  bbox=[0, 426,  81,  54]   ← 贴左边缘
```

**根因**：检测器**只有 `area < 200` 一个尺寸过滤** —— 没有上限、没有贴边判断、
没有长宽比判断；而分类器的"受限同色兜底"会把**任何形状的黑色块**判成核心物资
（BLACK 在初赛配置表里唯一）。

**修复**（三条判据全部由相机几何推出，不是魔数；外加一条分类器判据）：
1. **地平线以上不可能是贴地物体**：`v_h = cy − f·tan(tilt)` = 第 7.7 行；
   物资高 ≤120mm 而相机高 210mm ⇒ 物资顶端永远低于相机 ⇒ 成像永远在地平线以下。
   那团腿的顶边在 y=0，**比地平线还高 8 行**。
2. **被画面左右边缘裁掉的轮廓不可信**（宽度未知 → 测距与形状判定都失真）。
3. **长宽比 >3 不可能**（30° 俯视会纵向拉长，但拉不到 3 倍；腿是 378/100=3.8）。
4. **形状 UNKNOWN 不许走同色兜底** —— 兜底的初衷是"形状判错救回来"，
   而 UNKNOWN 是**根本没判出形状**，没有形状可救。

**护栏**：`verify_detector_ground_gates.py` —— **两边都测**，重点是**不许误伤真物资**：
用正向几何把 40mm 物资投影到 150/300/500/800/1100mm，全部通过。

## 4. 看到绿色/橙色却不抓：数据关联阈值定死 100mm

**根因**：`WorldMap.ASSOCIATION_DISTANCE_MM = 100`，而**同一个物体**的逐帧位置估计
抖动实测就有 48~95mm。

**更要紧的一层机制**：待确认缓冲对位置做了 **50/50 平滑**，候选点每次都滞后，
从平滑后位置到下一个检测的距离 ≈ **1.5 × 原始抖动** ⇒ **有效容忍度只有阈值的约 2/3**
（100mm → ≈66mm）。

| 数据 | 逐帧抖动 | 旧阈值(100mm) | 结论 |
|---|---|---|---|
| run1 绿块 | 最大 58.9mm | 通过 | **侥幸**（离 66mm 只差 7mm） |
| run3 绿块 | 93.7mm | **0 个确认目标** | 必挂 → 决策层看不到可抓目标 → 转探索 |

**修复**：阈值改为随距离自适应 `max(100, 0.30×车到目标距离)`，上限 450mm
（测距误差 ∝ 距离²，近处保持小阈值避免把相邻物体并成一个）。
**护栏**：`verify_worldmap_association.py`，A 场景用**现场真实抖动序列**复现旧 bug，
B 验证新阈值能确认，C 反向验证"相距 300mm 的两个物资不会被并成一个"。

## 5. 夹爪下压了却被自己否掉：`SLEEVE_ROI` 没标定 + 开关没接线

**现象**（用户报"它就是不把夹爪放下来去抓绿色"）：
```
transport_pipeline: 到达目标附近: dist=71mm — 已显式停车，开始套取
sleeve_lift: SERVO,LOWER 套住: 1 个目标              ← 夹爪**确实下压了**
transport_pipeline: 视觉确认：套取框内未见目标 → 判为套取失败，将抬爪后退重试
sleeve_lift: SERVO,RAISE 抬起释放                    ← 1 秒后又抬起
```
从外面看就是"它根本不去抓"。

**根因**：
- `Camera.SLEEVE_ROI = (0.32,0.55,0.68,0.98)` 是**旧夹爪**标的值，而夹爪 V2 换成
  150×100 方口、后方还有三块实心板 → 确认**永远**判"没套住"；
- `Camera.SLEEVE_CONFIRM` 这个开关**全仓只被定义、从没被读取** ——
  配置注释写着"ROI 未标定/看不到槽时可先关掉"，但代码里根本没有这条路。

**修复**：
- 把 `SLEEVE_CONFIRM` 真正接上（环境变量 `SLEEVE_CONFIRM=0` 或 YAML 都能关）；
- 新增 `tools/calibrate_sleeve_roi.py`：把物资放进槽里跑一次，
  自动挑出位置最稳定的检测并算出归一化 ROI，**直接打印可粘贴的配置行**；
- 把 ROI 黄框画到实时画面上，标注 `SLEEVE_ROI ON in=N -> OCCUPIED/EMPTY`
  （与 `check_sleeve_occupied` 同一判据），标定变成"看一眼"。

## 仍然未解决

   能过几何门 ⇒ 是形状正常、位置合理的黑色块。**怀疑是夹爪 V2 那三块黑色实心板
   进了视野**，需要一张实时画面截图确认。
2. **夹爪 V2 若后方实心板挡住槽口** → 视觉确认对 V2 根本不可用，只能用
   `SLEEVE_CONFIRM=0` 运行。
3. **定位精度的两个数还没量**（`tools/pose_accuracy_check.py`）。
   量出来才能决定要不要做视觉闭环/路标锚定 —— 注意：
   **用视觉去修 odom 的恒定偏移是无效的**（地图坐标与当前测量同时偏 δ，差值恒为 0），
   视觉能做的是**闭环对准**（对偏移免疫）和**漂移检测**（只能发现建图之后新产生的漂移）；
   真正的绝对锚定要靠**已知坐标的路标**（安全区紫围栏/出发区洋红方块）。
   但距离换算对像素极敏感：底边每错 1 像素，264mm 处 = 1.1mm、1100mm 处 = **14.7mm**、
   2037mm 处 = **48mm**、4948mm 处 = **269mm** ⇒ 只适合做**近场**锚定。
4. **`run.sh` 里硬编码 `SKIP_CAMERA_CHECK=1`** —— 现场摄像头掉过线，
   现在它死了也不会在赛前拦住。
5. 直行跑偏（实测 Δθ 5~24°）与里程计 4~8% 的尺度误差。
