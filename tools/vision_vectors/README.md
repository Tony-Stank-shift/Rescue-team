## 目录内容

| 文件 | 作用 |
|---|---|
| `generate_vectors.py` | 确定性合成图生成（固定种子、不依赖摄像头/网络），产出 `img/*.png` |
| `samples.py` | 样本定义（颜色 × 形状 × 尺寸，含回归样本） |
| `run_vectors.py` | 逐样本跑当前 `detection.py` 的 HSV 判定，打印颜色中心与命中的桶 |
| `vectors.json` | 向量清单（schema / 生成者 / 是否确定性 / 帧尺寸 / 底色） |
| `img/` | 生成的样本图（36 个） |

## 现场怎么用

```bash
# 1) 看当前阈值对这批样本的判定（不需要相机）
PYTHONPATH=src python3 tools/vision_vectors/run_vectors.py

# 2) 用真实相机标定 HSV（现场灯光下）
python3 tools/vision_calibration.py
```

`run_vectors.py` 的输出里有两类**现场必须知道**的信息：

1. **参与检测的颜色桶是有顺序的**：初赛/决赛当前都是
   `['LIGHT_BLUE', 'GREEN', 'BLACK', 'ORANGE']`。
2. **BLUE 与 LIGHT_BLUE 的 HSV 桶在 H∈[95,110] 区间重叠**，重叠区由**检测顺序**决定取
   `LIGHT_BLUE`（即被判成**危险目标**）。这是**必须现场标定**的项目：真机的浅蓝与蓝
   在该区间本质重叠，只能靠"浅蓝先检测 + 分类器禁止容差命中 DANGEROUS"两道闸门区分
   （见 `docs/audit/FIXES.md` 的待现场标定表）。

## 已知回归样本（延续 t15 的设计意图，供继续完善时使用）

| 样本 | 为什么必须有 |
|---|---|
| `vec_04_*_orange_cuboid_80x40.png` | 80×40 扁盒 → 必须是 `CUBOID`。旧实现与立方体判据重叠会判成 `CUBE` → **伤员必误判（丢 15 分/个）** |
| `vec_03_normal_lightblue_dangerous*.png` | 纯饱和蓝 / 浅蓝 → **绝不能**判成 `DANGEROUS` |
| `vec_05_orange_cuboid_front40x40.png` | 长方体 80 面正对短边（投影 40×40）—— **单目轮廓无法与正方体区分**，这是已知的**根本不可区分项**，需靠颜色 + 比赛阶段组合裁决 |
